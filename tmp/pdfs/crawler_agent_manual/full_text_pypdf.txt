2.1 爬虫任务完整流程
面试官最容易用开放题考你：“给你一个外包平台/招聘网站/榜单/论坛，你怎么采？”你必须先把流程讲清
楚，而不是直接说“我用 requests”。
你要掌握的流程
• 明确业务目标：为什么采、采给谁用、最终要分析什么。
 
• 定义字段：字段名、字段类型、来源页面、是否必填、是否唯一。
 
• 分析页面：静态 HTML、XHR/API、动态渲染、登录态、分页。
 
• 选择工具：requests 处理接口，BeautifulSoup/XPath 处理 HTML，Selenium/Playwright/DrissionPage 处理浏览
 器场景，Scrapy 处理工程化。
• 稳定采集：timeout、retry、限速、日志、失败任务记录、断点续爬。
 
• 解析保存：HTML/JSON 解析，写 CSV/Excel/数据库。
 
• 清洗质检：重复、缺失、异常、类型、时间、枚举、字段一致性。
 
• 交付沉淀：结构化表、分析结论、字段字典、Markdown 流程。
 
标准回答模板
我会先确定业务字段，再用开发者工具判断数据来自 HTML、XHR/API 还是动态渲染。接口能复现就优
先用 requests/httpx；需要点击、滚动、登录或 JS 执行时用 Selenium/Playwright/DrissionPage；长期结构化
项目用 Scrapy。采集时处理分页、headers、Cookie、timeout、retry 和限速；采集后用 pandas 做清洗和质
量检查，最终输出 CSV/Excel 和流程文档。
2.2 HTTP / HTTPS / URL 基础
HTTP 是爬虫的地基。你不需要一开始背 TLS 的每一步，但必须知道请求和响应的基本结构。
URL 结构
https://www.example.com:443/search/list?page=2&keyword=python#section1
协议        域名             端口 路径         查询参数                  锚点
• 协议：http 或 https。https 表示在 HTTP 基础上使用 TLS 加密。
 
• 域名：目标服务器地址，例如 www.example.com。
 
• 路径：服务器资源位置，例如 /api/list。
 
• 查询参数：?page=2&keyword=python，通常用于搜索、分页、筛选。
 
• 锚点：#section1，通常只在浏览器端定位页面位置，不会发给服务器。
 
HTTP 请求流程
输入 URL
  -> DNS 把域名解析成 IP
  -> 建立 TCP 连接
  -> 如果是 HTTPS，进行 TLS 加密协商
  -> 发送 HTTP 请求：method + path + headers + body
  -> 服务器处理请求
  -> 返回 HTTP 响应：status code + headers + body
  -> 客户端解析 HTML / JSON / 图片 / 文件

面试回答：403 怎么办
我不会无限重试。先检查浏览器请求和 Python 请求的差异：URL、method、headers、Cookie、Referer、
Origin、params/payload、登录态。然后判断是否是权限问题、频率问题、动态参数问题或数据源限制。
能合法补齐会话状态就补齐；频率问题就降速；接口参数问题就回到 Network 分析。
面试回答：429 怎么办
429 表示触发限流。我会降低并发、增加随机 sleep、使用指数退避重试、控制单 IP/账号请求频率，并记
录失败 URL 后续重跑。
2.6 浏览器开发者工具 Network
Network 是你面试里最要讲得像“真实做过”的工具。面试官常问：你怎么找到接口？你怎么处理分页？你
怎么知道参数变了？
Network 分析步骤
• 打开开发者工具，进入 Network。
 
• 勾选 Preserve log，避免跳转或刷新后请求消失。
 
• 筛选 Fetch/XHR，重点看接口请求。
 
• 刷新页面，观察初始接口。
 
• 执行动作：搜索、翻页、点击、滚动，观察新增请求。
 
• 点开请求，查看 Headers、Payload、Preview、Response。
 
• 复制 URL、method、params、payload、headers，用 Python 复现。
 
• 对比第一页和第二页参数，找 page/offset/cursor/max_id。

2.7 requests 实战基础
import requests
session = requests.Session()
headers = {
    "User-Agent": "Mozilla/5.0",
    "Referer": "https://example.com/list",
    "Accept": "application/json, text/plain, */*",
}
params = {"page": 1, "keyword": "python"}
resp = session.get(
    "https://example.com/api/projects",
    headers=headers,
    params=params,
    timeout=10,
)
print(resp.status_code)
data = resp.json()
requests 重点清单
• requests.get(url, params=params)：GET 查询。
 
• requests.post(url, json=data)：发送 JSON 请求体。
 
• requests.post(url, data=data)：发送表单请求体。
 
• headers：模拟浏览器请求环境。
 
• timeout：避免请求永久卡住。
 
• Session：保持 Cookie 和连接复用。
 
• response.text：文本响应，常用于 HTML。
 
• response.json()：JSON 响应，常用于 API。
 
• response.content：二进制内容，图片、文件、PDF。
 
面试回答：requests.Session 有什么用
Session 可以在多个请求之间保持 Cookie 和连接状态，比如先访问首页拿到 Cookie，再请求列表页、详
情页、评论接口时自动携带 Cookie。对需要会话状态的网站，Session 比每次单独 requests.get 更稳定。

2.9 API / JSON 解析与嵌套结构
data = resp.json()
items = data.get("data", {}).get("items", [])
rows = []
for item in items:
    rows.append({
        "project_id": item.get("id"),
        "title": item.get("title"),
        "budget": item.get("budget"),
        "tags": ",".join(item.get("tags", [])),
        "publisher": item.get("user", {}).get("nickname"),
    })
JSON 清洗原则
• 先保存原始 JSON 样本，方便回溯和重跑。
 
• 用 get + 默认值，避免 KeyError。
 
• 嵌套 dict 逐层 get；嵌套 list 根据业务展开多行或拼接。
 
• 二级评论保留 parent_id，还原父子关系。
 
• 字段缺失要统计缺失率，不是随便填。
 
• 输出表格时字段名要稳定，不要一会中文一会英文。
 
面试回答：复杂嵌套 JSON 怎么办
我会先抽样观察 JSON 层级，保留原始响应。解析时使用 get 和默认值处理缺失字段；list 字段根据业务
展开或拼接；父子评论保留 parent_id；最后转成 DataFrame 后检查缺失率、重复值和字段类型。

    items = data.get("data", [])

    if not data.get("has_more"):

面试回答：如何处理分页
我会在 Network 中对比翻页或滚动时的请求，判断分页参数类型。如果是 page 就递增页码；offset/limit
就递增 offset；cursor 就用接口返回的 next_cursor；停止条件是 has_more=false、next_cursor 为空、返回列
表为空或达到页数上限。

import time, random, requests
def fetch_with_retry(url, headers=None, params=None, max_retries=3):
    for attempt in range(1, max_retries + 1):
        try:
            resp = requests.get(url, headers=headers, params=params, timeout=10)
            if resp.status_code == 200:
                return resp
            if resp.status_code in (500, 502, 503, 504):
                time.sleep(2 ** attempt + random.random())

七、高频面试题回答模板
1. 给你一个网站，你怎么采？
先明确业务字段，再判断数据来源。看 HTML 是否有数据；没有就用 Network 找 XHR/API；能复现接
口就用 requests/httpx；需要登录、点击、滚动或 JS 渲染就用 Selenium/Playwright/DrissionPage；长期维护
用 Scrapy。采集时处理分页、headers、Cookie、timeout、retry、限速，采集后用 pandas 清洗并输出
CSV/Excel。
2. requests 和 Selenium 区别？
requests 是 HTTP 请求库，适合接口和静态网页，速度快、资源少；Selenium 是浏览器自动化，适合动态
渲染、登录、点击、滚动等需要真实浏览器的场景。实际优先找接口，找不到或必须交互时再用浏览器。
3. Scrapy 和 requests 区别？
requests 更适合简单脚本；Scrapy 是工程化爬虫框架，有 Spider、Item、Pipeline、Middleware、settings、
请求调度、并发和去重机制，适合多页面、多字段、长期维护项目。
4. Cookie 和 Session 区别？
Cookie 存客户端，Session 通常在服务端。服务端通过 Cookie 里的 session_id 找到会话状态。爬虫里常用
requests.Session 维持 Cookie，避免每次请求状态丢失。
5. 动态渲染是什么？
初始 HTML 里没有目标数据，页面加载后 JavaScript 请求接口并渲染数据。requests 直接拿页面可能拿不
到数据，需要找接口或用浏览器自动化等待 JS 执行。
6. 如何处理分页？
在 Network 中观察翻页/滚动请求，判断是 page、offset、cursor、max_id 还是 has_more。不同分页方式用
不同循环，停止条件是 has_more=false、next_cursor 为空、列表为空或页数上限。
7. 403 怎么办？
先检查请求和浏览器请求差异：URL、method、headers、Cookie、Referer、Origin、params/payload、登
录态。判断是权限、频率、参数还是数据源限制。不能盲目无限重试。
8. 429 怎么办？
说明请求过快。降低并发，加入随机 sleep 或指数退避，控制单 IP/账号频率，记录失败 URL 后续重跑。
9. JSON 嵌套很深怎么办？
先保存原始 JSON，抽样观察结构。解析时用 get 和默认值；list 根据业务展开或拼接；父子评论保留
parent_id；转 DataFrame 后检查缺失、重复、类型。

    "Referer": "https://example.com/list",
}
rows = []

    params = {"page": page, "page_size": 20}
    resp = session.get("https://example.com/api/list", headers=headers, params=params, timeout=10)
    if resp.status_code == 429:
        time.sleep(10)
        continue
    if resp.status_code != 200:
        print("failed", page, resp.status_code)
        continue
    data = resp.json()
    items = data.get("items", [])
    if not items:
        break
    for item in items:
        rows.append({
            "id": item.get("id"),
            "title": item.get("title"),
            "created_at": item.get("created_at"),
        })
    time.sleep(random.uniform(1, 2))

12.1 HTTP 报文到底是什么
HTTP 请求不是一句“访问 URL”那么简单，它由请求行、请求头、空行、请求体组成。响应由状态行、响
应头、空行、响应体组成。爬虫复现接口时，本质上是在复现浏览器发出的 HTTP 请求。

12.3 编码、乱码、二进制响应
• HTML 文本乱码：检查 response.encoding、apparent_encoding、页面 meta charset。
 
• CSV 中文乱码：导出给 Excel 时常用 utf-8-sig；国内老数据可能是 gbk。
 
• JSON 一般是 UTF-8，但也可能包含转义字符。
 
• 图片、PDF、视频等用 response.content，不要用 response.text。
 
• 保存二进制时用 wb 模式。
 
# 保存图片/PDF
resp = requests.get(file_url, timeout=10)
with open("file.bin", "wb") as f:
    f.write(resp.content)
12.4 CORS、CSRF、Token：知道到什么程度
CORS 是浏览器的跨域安全策略，主要限制浏览器脚本，不直接限制 Python requests。CSRF Token 是网站为
了防止跨站请求伪造设置的校验参数，可能出现在表单、Cookie、meta 标签或接口返回里。Token 则常用于
认证授权。

12.6 Scrapy 请求生命周期
Scrapy 面试深挖时，常问“一个请求在 Scrapy 里怎么流转”。
Spider 产生 Request
  -> Scheduler 调度请求
  -> Downloader Middleware 处理请求，如 UA/代理/Cookie
  -> Downloader 发起网络请求
  -> Response 返回
  -> Spider Middleware 处理响应
  -> Spider parse 解析出 Item 或新的 Request
  -> Item 进入 Pipeline 清洗/去重/保存
  -> 新 Request 继续进入 Scheduler
深挖回答
Scrapy 的优势是把请求调度、并发、去重、下载、解析、数据保存拆成模块。项目变复杂时，比单个
requests 脚本更容易维护。

14.3 数据质量回答公式：完整性 -> 唯一性 -> 合法性 -> 一致性 -> 可追溯
• 完整性：字段是否缺失、采集页数是否完整。
 
• 唯一性：主键是否重复。
 
• 合法性：数值范围、时间格式、枚举值是否合法。
 
• 一致性：多来源字段名、单位、类型是否统一。
 
• 可追溯：保留原始数据、清洗规则、行数变化。

15.2 必背 8 句话
• 优先找接口，找不到或必须交互时再用浏览器自动化。
 
• 403 不盲目重试，先检查 headers、Cookie、Referer、Origin、权限和参数。
 
• 429 是限流，要降并发、随机 sleep、指数退避和失败记录。
 
• 分页先用 Network 对比参数，常见 page、offset、cursor、max_id、has_more。
 
• JSON 清洗要保留原始数据，用 get 处理缺失，父子评论保留 parent_id。
 
• 数据质量检查看字段完整性、重复主键、缺失率、异常值、类型和时间格式。
 
• Scrapy 的核心是 Spider、Item、Pipeline、Middleware、settings。
 
• Agent 需要结构化、稳定、可解释的数据，否则容易产生错误分析。
